# Tribune watchdog（GAS）— 朝刊未発行の検知

C186 (2026-08-29)。GitHub Actions の schedule 不発・遅延で朝刊が欠けたとき、
神山さんが気づく前にメールで知らせる。**認証情報を一切持たない**（リポジトリが
PUBLIC なので読み取りだけで済む）。

対象ファイル：[`tribune_watchdog.gs`](tribune_watchdog.gs)

## 何を見ているか

| 層 | 見る先 | 分かること |
|---|---|---|
| 生成 | `raw.githubusercontent.com/.../main/archive/<日付>.html` | 紙面が生成され commit されたか |
| 発行 | 公開サイトの `index.html` の `data-date` | デプロイに反映されたか |

2 層に分けているのは「未生成」と「生成済みだがデプロイ未反映」を切り分けるため。
後者は 2026-06-23 に実際に起きている（`daily.yml` の C93 コメント）。

GitHub REST API（contents）は使わない。未認証だと 60 req/時/IP の制限があり、
GAS は Google の共有 IP から出るため 403 を踏みうる。

## セットアップ

1. <https://script.google.com/> で「新しいプロジェクト」を作成。
   名前は `Tribune watchdog` など。

2. 既定の `Code.gs` の中身を全部消し、`tribune_watchdog.gs` の内容を貼り付けて保存。

3. **タイムゾーンを Asia/Tokyo にする**（重要）。
   左の歯車「プロジェクトの設定」→「タイムゾーン」→ `(GMT+09:00) 東京`。
   これを忘れるとトリガーが JST でない時刻に発火する。

4. 公開サイトの URL を確認する。既定は GitHub Pages
   （`https://akiokamiyama-ai.github.io/kt-paper-1caa/`）。
   **神山さんが普段 Vercel 側を読んでいるなら `PUBLISHED_URL` をその URL に
   差し替える**（末尾スラッシュあり）。実際に読んでいる面を見張る方が意味がある。

5. 動作確認（メールを送らない）。関数選択で `dryRunToday` を選び実行。
   初回は Google の認可ダイアログが出るので許可する
   （外部 URL への接続とメール送信の権限）。
   実行ログに `{"generated":true,"published":true,...}` が出れば OK。

6. メールの疎通確認。`sendTestMail` を実行すると、件名が `[TEST] ...` の
   メールが 1 通届く。本文に手動実行の手順が入っていることを確認する。
   届かない場合は迷惑メールも確認。

7. トリガー設定。`setupTrigger` を 1 回だけ実行する。
   左メニューの「トリガー」に `checkTribune` の日次トリガーが登録される。
   同名トリガーは作り直されるので、何度実行しても重複しない。

## 通知先

既定では**スクリプト所有者自身**（`Session.getEffectiveUser()`）に送る。
このリポジトリは PUBLIC なのでメールアドレスをコードに書かないこと。

別の宛先にしたい場合は「プロジェクトの設定」→「スクリプト プロパティ」に
`NOTIFY_EMAIL` を追加する。

## 検知時刻をなぜ 05:30 にしたか

archive commit の実着弾時刻（JST、2026-08-15〜08-28）:

```
03:05 03:06 03:07 03:07 03:17 03:21 03:23 03:24 03:25 03:26 03:27 03:50
04:44  ← 8/27、+107 分の遅延
09:07 / 11:10  ← 8/28、手動 + 遅延 schedule の二重実行
```

通常の最遅は 03:50、自動での最遅は 04:44。神山さんの起床は 6:30。

| 時刻 | 評価 |
|---|---|
| 03:30 | 通常時ですら間に合わない日がある。誤検知が多すぎる |
| **05:30** | 通常最遅 +100 分 / 自動最遅 +46 分 / 起床の 60 分前。**直近 14 日で誤検知ゼロ** |
| 07:00 | 余裕は最大だが起床後なので神山さんが先に気づく |

**遅延はスキップと違って「後から出る」**ので、早すぎる検知は「まだ出てないだけ」を
拾う。逆に遅すぎると通知の意味が無い。

変えたい場合は `CHECK_HOUR` / `CHECK_MINUTE` を書き換えて `setupTrigger` を
再実行する。

なお GAS の時間トリガーは指定時刻から **±15 分のブレ**がある（仕様）。05:30 なら
実際の発火は 05:15〜05:45。上の余裕はこのブレを吸収できる幅にしてある。

## 動作確認用の関数

| 関数 | 動作 |
|---|---|
| `dryRunToday` | 今日の実際の状態をログに出す。メールは送らない |
| `dryRunMissing` | 存在しない日付（2099-01-01）で検査し、件名と本文をログに出す。メールは送らない |
| `sendTestMail` | `[TEST]` 付きのメールを 1 通送る。`lastNotified` を汚さない |

## 正常時は無通知

生成・発行の両方が OK なら何もしない。メールが来ないことが正常。

同じ日に重複してメールを送らないよう、スクリプト プロパティの `lastNotified` に
通知済みの日付を記録している。
